A T3 Code user complained that a provider went down for lack of capacity, and the thread sat idle for six hours during the night. The user asks for T3 Code to ping the provider at intervals by itself until it comes back.

Theo answers with two points. First, as far as he knows, Codex itself doesn't do this. Second, he doesn't want to cause a thundering herd for OpenAI. That's when thousands of clients retry requests to a downed service at once and keep it from recovering. So he doesn't promise auto-retry in T3 Code.

For himself he has a manual workaround:
1. Start a separate thread on Haiku (the cheapest Claude model).
2. Run it on a schedule every 15 minutes.
3. That thread's job is to check the Codex thread and "bump" it if it's stuck.

The post doesn't say what he uses for the schedule. T3 Code has scheduled tasks, so probably those, but that's my guess.
