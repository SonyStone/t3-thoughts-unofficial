Ganesh asks whether T3 Code's design has room for a "verification thread" with permission to reject a change, one that checks a coding agent's work before it counts as finished. Or should that gate live outside the harness?

Theo replies: "You can just prompt this lol. No need for a "feature"."

His PR from the same day shows what this looks like in practice. Before the merge, the Opus 5.5 code went through a review round by GPT-6.1 Sol, and the verdict was approved. He didn't point to that PR as an example himself, the connection is mine. As steps:
1. In the agent's task, say that before finishing it has to hand its changes to another model for review.
2. The reviewer gives a verdict.
3. If the change is rejected, the agent reworks it and sends it for review again.
